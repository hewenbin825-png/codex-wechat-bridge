# 微信任务问答

用户安装并启用桥接后，本技能作为本机主任务的默认工作流；主任务启动或恢复时自动应用，无需反复点名。SessionStart 注入本技能指引；MCP 启动和后台健康检查负责拉起、恢复本机服务。单纯看到 skill 文件不能代替服务可用、手机实收和答案回填验收。

用户要求使用 GPT/Codex 原生问答界面，不使用自绘弹窗。普通问题可以在微信或电脑本地回答，主任务轮次结束发送微信简短摘要；子智能体完成不通知。优先使用已配置的 `mcp__wechat_bridge__ask_user`，每次调用只放一道题，带稳定 `id`、`question` 和可选 `options`（`label`、`description`）。一次需要 1–3 题时，使用不同 request_key 独立调用，可并发等待。同一道题只接受先到的有效答案，返回当前原聊天的同一调用。

## 电脑与微信双端回答

- 使用 GPT/Codex 原生问题卡。新连接状态为 `mcp_client_revision=native-mcp-v2`、`local_form_provider=codex_native`；旧连接需要重新加载。手机有效回答后对原生卡发出对应取消请求，保留原答案并丢弃迟到响应；必须以真实客户端关闭验收为准，不能把取消通知已经发出当作窗口已关闭。管理页只是额外入口，不能替代原生界面。无法显示本地卡时，直接在 Codex 问询，不用自绘窗口替代。
- 同题同时经原生入口和微信呈现时，保持题目及选项对应关系，只消费先收到的有效真实答复，并结束另一端的等待；迟到的重复答复不创建新任务、不覆盖原答案。原生卡片的用户回执与桥接自动表单应分别记录验收结果。
- 支持 MCP 表单的客户端显示原生问题卡；本机管理页提供额外回答入口。原生 `request_user_input` / `request_user_input_async` 仍允许使用，不得因微信在线而拦截。
- 在原 Codex 聊天直接提供的真实用户答案同样有效。若它中断了等待中的桥接调用，使用这条本地答复继续，并结束对应旧待答；不要要求用户必须再去微信回复。
- 微信或电脑端先提交的有效答案生效。另一端迟到答案不得覆盖；取消、过期、关闭本地表单及发送失败都不是用户答案。关闭本地表单不取消仍有效的微信问题。
- 本机管理页无需等待微信在线才能回答。原生问题卡片需新 MCP 连接生效；老聊天重新加载前仍可在管理页回答。

### 微信答案回填原生框

用户明确允许把自己的微信答案填写到对应电脑普通问题框后，工作 Agent 在收到 `source=wechat` 的真实答案时自动完成回填，无需用户再在电脑答一次。先检查 `native_form_followup`；旧 MCP 没有此字段时，可用 `check_answer(request_id)` 读取本聊天原题及真实答案。

- 只处理同一原聊天、题号、标题和题干匹配的桥接普通问题；卡片已关闭就不重开。原生卡取消通知未能关闭时，使用已启用的 computer-use 按实际界面回填：选项匹配真实答案；自定义文字原样输入。用户电脑端先答或来源不明时不代填。
- 先核对匹配题目，再填写、提交，并读取一次紧随提交的界面反馈。提交后立即结束本次 computer-use 控制，释放回填用的 JS 会话；不继续点击其他界面、不常驻控制。下一道题需要时再启用。显示失败、匹配不唯一、桌面锁定或用户按 Esc 中止时停止，不猜坐标、不重复提交；不能把中止当作回填成功。
- 此授权仅覆盖本人已提交答案的普通问答，不覆盖执行权限审批、登录、安全设置或其他窗口。安装公开 skill 不自动授予原生界面代填权限；沿用用户当次或个人长期指令中的明确授权。
- 桥接中保留先到的微信答案，电脑回填只是完成同一题的原生提交流程，迟到的本地响应不覆盖它。原生卡真正关闭与“已发取消通知”分开验收。

## 用户回复约定

- 当前只有一道待答题：用户可只发纯净的 `1`、`2` 等选项号；其他文字原样作为该题自定义答案，无需“自定义：”前缀。
- 同时有多题：`1.1` 表示第 1 题选第 1 项；`2.2` 表示第 2 题选第 2 项；`2.这样改` 或 `（2.这样改）` 表示第 2 题自定义回答“这样改”。点号前为题号，后为选项号或自由文字。
- 题号以桥接消息显示为准，由本机桥接持续分配并保存；同一轮编号内跨聊天不重复，答完不重排，服务重启后保持稳定。用户主动发送微信 `/clear` 后开始新一轮编号。
- 发给用户的问题只需题号、问题、选项和一句简短回复说明。普通操作无需用户输入随机 Q 编号、线程 ID 或请求 ID。

只把实际用户提交的答案用于对应题目；不把微信任意消息或自定义文字解释成新的无限范围任务。多题时若缺题号或题号无效，提示用户按显示的题号回复，不猜测所属聊天。

## 答完后的题号补充

- 已答第 5 题后仍可发送 `5.按完 k4 后又按了 k5`，也支持 `（5.补充内容）`。这是第 5 题的后续提示词，投递到该题对应原主聊天，保留原答案，不新建聊天或分配任务号。
- 题号映射使用本机保留的问答记录，答完不重排；当前记录保留 7 天。未知、已取消、已过期或已归档来源不猜测聊天。
- 重复纯数字答案（例如答完再发 `5.1`）不当作补充或新任务。桌面连接短暂断开时只在本次调用内最多等待 15 秒恢复；仍不可用就明确尚未提交，不留下之后暗中执行的队列。有效备用连接可以接管，结束的连接主动注销，不将补充解释为执行许可。

## 清理问答编号

用户在微信发送 `/clear`，同时清理题号和任务号，包括艾莉丝创建的任务号。取消所有待答普通问题及尚未投递的编号补充、续办；旧编号入口失效，下一道问题和下一个新分配的任务都从 1 开始。工作聊天、问答与任务编号历史、完成去重记录保留；已经开始执行的工作不因此停止。旧聊天的新一轮完成可重新分配当前编号，迟到的旧回执不能修改重用同一数字的新任务。清理后只使用新消息里的编号。`/clear` 是本机桥接的保留命令，不交给 Dot 创建工作，也不作为任务续办提示词。取消不是用户答案；需要继续询问时应新建问题。此处是微信命令，不替代 Codex 自身的原生 `/clear`。

## 完成后继续原任务

- 完成通知显示当前编号轮次中的固定任务号和原聊天名称。任务号与题号分别编号，重启后保持；微信 `/clear` 同时重置两者，不给子智能体分配任务号。
- 用户发送 `/1 继续任务` 或 `/2 具体下一步要求`，只续办对应原主任务，不新建聊天。
- 只有一个可续办主任务时，`/继续任务` 或 `/任意下一步提示词` 可省略任务号。多个任务可续办时必须明确任务号，不能默认最新任务。`/任务` 查看列表。
- 无斜杠的选项号及自定义文字回答待答题；带已答题号的补充只投递该题原聊天，不启动其他任务。斜杠提示词也不是命令、文件、网络或其他执行权限审批。
- 续办需本机桌面连接可用。已收到、已提交到原聊天、投递未确认分别如实反馈。连接未就绪不声称已执行；结果不确定不自动重发。

## 调度与工作上下文

微信 `/艾莉丝 对话` 进入连续对话；`/艾莉丝 文字` 默认也是与艾莉丝直接交谈，不创建本机工作聊天或分配任务号。连续对话开启后，无待答问题的普通文字交给艾莉丝；待答题答案、题号补充、任务号续办、`/clear` 等原有指令优先按原路由处理。`/艾莉丝 退出对话` 结束连续对话，重启保留当前模式。

只有明确的 `/艾莉丝 创建任务 具体要求`（或 `/新任务 具体要求`）才能请求独立工作聊天。`/艾莉丝 继续任务 任务号 下一步要求` 只续办明确编号的已登记聊天；不能从普通闲聊、建议、引用的“创建任务”字样推断用户要求开任务。调度 MCP 的 `read_dispatch_request` 返回 `intent=conversation` 时，用 `reply_to_owner` 直接答复；仅 `intent=task` 可按记录的 action 和 target 领取及执行调度。服务器也拒绝把普通对话或迁移前未明确分类的旧消息转成新工作。

桥接负责消息收发、编号和确定性路由。采用 Dot 调度时，由 Dot 为独立工作创建或续办对应工作会话；工作上下文、项目目录和执行记录保留在各自会话，调度侧只接收任务引用、状态、必要摘要和产物引用。用户明确指定题号或任务号时返回原会话，不让调度层重新猜测或新建。实际 Dot 接口或事件订阅未联通前，不宣称已经接入或开始调度。

启用本机 Codex 调度后，Dot 先读取本人请求，以 `prepare_dispatch` 选择创建或续办，再用 `dispatch_work_chat`。该入口仅接收原请求 ID，本机连接器使用微信认证原文调用官方 Codex App Tools，独立新聊天不继承调度对话历史；不接受 Dot 额外提供的命令、目录、模型或审批覆盖。不以普通 `cloud_threads.create` 的 Work 任务代替明确要求的 Codex 会话。pending 时读回原请求状态；uncertain 时先核查，不重复创建。真实 threadId、任务号及完成通知由本机登记与去重。

## 完成通知与故障处理

完成摘要由本地 Stop 钩子发送，桌面连接可补充检测；两者按原聊天和轮次去重，不再额外调用发送工具重复通知。保留原桌面和艾莉丝通知配置。仅通知主任务，子智能体完成不发送。摘要如实表达本轮结果，失败或未完成时不能改写为任务成功。

工具未加载或返回 unavailable、error、expired、cancelled 时，直接在 Codex 问询，不将故障或超时当成用户答案。必要答案未到前不执行依赖它的工作。命令、网络、文件权限及其他执行审批仍走 Codex 正常审批，普通微信答案不作为执行许可。

桥接运行于当前用户 `.codex/codex-wechat-bridge`，管理入口为该目录的 `open-manager.ps1`。诊断连接时可调用 `mcp__wechat_bridge__get_status`。平台要求激活或登录恢复时使用既有“激活”或扫码流程，不自动更换账号、通道或扩大监听范围。
