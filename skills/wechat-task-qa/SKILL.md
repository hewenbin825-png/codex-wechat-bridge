# 微信任务问答

本技能在用户安装并启用桥接后，作为本机主任务的默认工作流；每个主任务启动或恢复时自动应用，无需反复点名技能。SessionStart 注入本技能指引；MCP 启动和后台健康检查负责拉起、恢复本机服务。单纯看到 skill 文件不能代替服务可用、手机实收和答案回填验收。

用户启用个人微信桥接后，按其选择优先发送普通问询，并只在主任务轮次结束时发送简短摘要；子智能体完成不通知。使用已配置的 `mcp__wechat_bridge__ask_user`，每次 1–3 题，每题带稳定 `id`、`question`，需要选择时提供 `options` 的 `label` 和简短 `description`。等待真实答案返回同一调用后继续原任务。

## 用户回复约定

- 当前只有一道待答题：用户可只发纯净的 `1`、`2` 等选项号；其他文字原样作为该题自定义答案，无需“自定义：”前缀。
- 同时有多题：`1.1` 表示第 1 题选第 1 项；`2.2` 表示第 2 题选第 2 项；`2.这样改` 或 `（2.这样改）` 表示第 2 题自定义回答“这样改”。点号前为题号，后为选项号或自由文字。
- 题号以桥接消息显示为准，由本机桥接持续分配并保存；跨聊天不重复，答完一题后不重排剩余题号，服务重启后保持稳定。
- 发给用户的问题只需题号、问题、选项和一句简短回复说明。普通操作无需用户输入随机 Q 编号、线程 ID 或请求 ID。

只把工具返回的答案用于对应待答题；不把微信任意消息或自定义文字解释成新的无限范围任务。多题时若缺题号或题号无效，提示用户按显示的题号回复，不猜测所属聊天。

## 完成后继续原任务

- 完成通知显示固定任务号和原聊天名称。任务号与题号分别编号，重启后保持，不给子智能体分配任务号。
- 用户发送 `/1 继续任务` 或 `/2 具体下一步要求`，只续办对应原主任务，不新建聊天。
- 只有一个可续办主任务时，`/继续任务` 或 `/任意下一步提示词` 可省略任务号。多个任务可续办时必须明确任务号，不能默认最新任务。`/任务` 查看列表。
- 无斜杠的选项号及自定义文字仍回答待答题；不启动其他任务。斜杠提示词也不是命令、文件、网络或其他执行权限审批。
- 续办需本机桌面连接可用。已收到、已提交到原聊天、投递未确认分别如实反馈。连接未就绪不声称已执行；结果不确定不自动重发。

## 完成通知与故障处理

完成摘要由本地 Stop 钩子发送，桌面连接可补充检测；两者按原聊天和轮次去重，不再额外调用发送工具重复通知。保留原桌面通知配置。仅通知主任务，子智能体完成不发送。摘要如实表达本轮结果，失败或未完成时不能改写为任务成功。

工具未加载或返回 unavailable、error、expired、cancelled 时，直接在 Codex 问询，不将故障或超时当成用户答案。必要答案未到前不执行依赖它的工作。命令、网络、文件权限及其他执行审批仍走 Codex 正常审批，普通微信答案不作为执行许可。

桥接运行于当前用户 `.codex/codex-wechat-bridge`，管理入口为该目录的 `open-manager.ps1`。诊断连接时可调用 `mcp__wechat_bridge__get_status`。平台要求激活或登录恢复时使用既有“激活”或扫码流程，不自动更换账号、通道或扩大监听范围。
