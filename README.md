# Codex 微信桥接 2.0

在微信接收本机 Codex 的主任务摘要，在微信或电脑回答问题，并让 Dot 艾莉丝调度独立的 Codex 工作聊天。

[下载 v2.0.0](https://github.com/hewenbin825-png/codex-wechat-bridge/releases/tag/v2.0.0) · [CSDN 功能说明](https://blog.csdn.net/2401_87974529/article/details/168767604) · [Dot 接入步骤](DOT_SETUP.md) · [验证记录](VALIDATION.md)

## 2.0 的功能

| 功能 | 使用效果 |
| --- | --- |
| 主任务通知 | 本轮结束后收到固定任务号和短摘要；失败、待办仍如实保留 |
| 子智能体静默 | 子智能体完成不发微信、不占任务号 |
| 微信与电脑双端问答 | 使用 GPT/Codex 原生问答界面，两端可选项或填文字，先到的有效答案生效 |
| 简短回复 | 单题直接发 `1`、`2` 或文字；多题按 `5.1`、`5.这样改` 回复 |
| 题号补充 | 已答题仍可发 `5.补充内容`，投递到该题原聊天 |
| 任务续办 | `/11 下一步要求` 返回任务 11；多个可续办任务时不默认最新任务 |
| `/clear` | 清空题号和任务号，取消待答，新问题和新分配任务均从 1 开始；工作聊天保留 |
| Dot 艾莉丝调度 | `/艾莉丝 新需求` 经私有事件连接，由本机官方 App Tools 创建独立 Codex 聊天 |
| 自动加载与恢复 | 默认 skill、当前用户登录启动、MCP 健康检查和连接恢复 |

## 调度与工作分开

```text
微信新需求 /艾莉丝 …
  → 本机桥接校验绑定用户
  → 私有 MCP 事件唤醒 Dot 艾莉丝
  → 艾莉丝读取请求并领取一次调度权
  → 本机官方 Codex App Tools 创建独立聊天
  → 工作聊天执行、提问、保存产物
  → 原有通知出口发送主任务短摘要
```

Dot 只保留任务引用、状态和必要摘要。具体工作的上下文与目录留在各自聊天中，创建提示词使用认证微信原文，不带入 Dot 的调度历史。

远端 `dispatch_work_chat` 只接受已经领取的本人请求 ID，不接受额外提示词、命令、目录、模型或审批覆盖。返回 pending 时读回原请求；结果不确定时不再次创建。普通题号和明确任务号按已有映射返回原聊天。

## 开始使用

环境：Windows、Node.js 24+、Python 3.11+，以及支持 MCP、Hooks 和本机 App Tools 的 Codex。微信需要具备对应 ClawBot 接入资格。Dot 为可选功能，需要账户具备相关权限并完成单独配置。

下载 Release 的公开源码包并解压，在项目目录用 PowerShell 运行：

```powershell
& .\Install.ps1
```

随后打开管理入口：

```powershell
& "$env:USERPROFILE\.codex\codex-wechat-bridge\open-manager.ps1"
```

扫码绑定，在微信 ClawBot 发送“激活”。如 Codex 提示钩子需要审阅，按原生流程完成审阅，再重新加载已有聊天。安装器会安装 `wechat-task-qa` skill 并写入主任务指引，之后无需反复点名技能。

基础微信问答与通知可独立使用。接入 Dot 时，按 [DOT_SETUP.md](DOT_SETUP.md) 创建自己的私有隧道、配置受限运行密钥、连接个人插件、订阅两类事件，并启用本机电脑访问。公开包不含他人的账号绑定、密钥、隧道配置或预装的私人插件。

## 微信回复与指令

| 发给 ClawBot 的内容 | 含义 |
| --- | --- |
| `1` 或 `先整理原因` | 只有一道待答题时选择或自定义回答 |
| `5.1`、`5.这样改` | 多题时回答显示的第 5 题 |
| `5.补充内容` | 已答题的后续补充，返回原聊天 |
| `/艾莉丝 整理这个需求` | 新需求交给 Dot 调度独立 Codex 工作 |
| `/11 继续整理结果` | 续办任务 11 的原聊天 |
| `/任务` | 查看任务号与状态 |
| `/clear` | 清理题号与任务号，两者重新从 1 开始 |
| `待答`、`状态`、`激活` | 查看问题、检查连接、恢复微信消息上下文 |

题号与任务号分别编号，在同一轮编号内保持稳定，重启保留。`/clear` 同时重置两者，包括艾莉丝任务号；取消待答和尚未投递的编号提示词，旧编号入口失效。工作聊天、编号历史和完成去重记录保留，已经开始执行的工作不会停止。清理后只使用新消息里的编号。此处 `/clear` 是微信桥接命令，与 Codex 自身的原生命令分开。

每道普通问题使用一次独立 `ask_user` 调用，多题可以并发；电脑使用 GPT/Codex 原生界面。当前桌面版本单靠取消通知仍可能不能即时关闭问题卡。用户明确授权原生框代填后，工作 Agent 收到真实微信答案时，使用已启用的 computer-use 匹配同一道题、选择选项或原样填写文字并提交；提交后立即结束本次电脑控制，下次需要时再启用。选项与自定义文字回填、卡片关闭均已实测；本地迟到响应不覆盖微信答案。

需要此回填功能时，在 Codex 明确说明“允许把本人微信普通答案回填到对应原生问题框，提交后立即结束 computer-use”。公开安装不自动授予代填权限。computer-use、可匹配的原生卡与可操作桌面须可用；无法操作时不宣称已经关闭，微信答案仍作为该题真实答案保留。执行审批不代填。

题号补充和任务续办遇到短暂断线时，在本次调用内最多等待 15 秒恢复；仍未连接则回报尚未提交，不遗留之后暗中执行的请求。多个已验证桌面连接可保持备用，当前连接退出后切换，不重复投递已执行的工作。

只有一个可续办任务时，`/继续任务` 可以省略任务号；多个任务可续办时必须明确选择。主任务通知表示本轮结束，并不把失败或未完成改写为成功。

## 自动启动与数据

微信桥接由当前用户登录任务启动，MCP 加载后也会检查并恢复服务。Dot 隧道另有持续运行的当前用户登录任务，使用 `-Watch` 每 15 秒检查受管连接，断开时重连同一隧道；启动命令退出后守护仍持续运行。二者都使用普通用户权限，不保存 Windows 密码。已主动停止受管连接并验证自动恢复；尚未实际重启 Windows，不承诺无人登录时运行。

本机管理服务只监听 `127.0.0.1:17349`。微信凭据、Dot 运行密钥由当前用户 Windows DPAPI 加密保存；数据库保留必要的问答和投递状态。完成摘要按原聊天与轮次去重，不上传完整聊天历史。创建独立工作只使用原请求，不意味着整个工具系统无法访问其他文件；实际权限仍由 Codex 管理。

普通问题可以两端回答，执行命令、文件、网络等审批仍走 Codex 原流程。连接不可用、问题取消或过期时不会代答；未知的投递结果不会自动重发。

`Uninstall.ps1` 移除微信桥接配置和登录启动，默认保留加密状态。已单独配置的 Dot 隧道及事件订阅需要按接入文档另行停用。
