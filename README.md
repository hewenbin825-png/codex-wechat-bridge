# Codex 微信桥接 2.1

需要时把某个 Codex 聊天的问题和完成摘要送到本人微信，也可以直接与 Dot 艾莉丝连续聊天。具体工作只有在明确要求创建任务时，才进入独立的本机 Codex 聊天。

[下载 v2.1.0](https://github.com/hewenbin825-png/codex-wechat-bridge/releases/tag/v2.1.0) · [验证记录](VALIDATION.md) · [Dot 接入](DOT_SETUP.md) · [技能](skills/wechat-task-qa/SKILL.md)

## 默认行为与按聊天开启

| 场景 | 电脑端 | 微信端 |
| --- | --- | --- |
| 新聊天、分叉聊天、Dot 新工作 | Codex 原生问题选择卡 | 不推送该聊天问题或任务信息 |
| 在该聊天明确说“微信通知我” | 粗体引用块显示问题，直接发提示词回答；不弹问题卡 | 问题提醒、主任务完成摘要；可回数字或自由文字 |
| 在该聊天要求关闭微信或恢复原始卡 | 恢复 Codex 原生问题卡 | 停止该聊天推送 |
| `/艾莉丝 对话` | 不新建工作聊天 | 与艾莉丝直接连续聊天 |

模式按聊天 ID 持久保存，互不影响，新聊天不继承。连接微信、加载 skill 或安装插件，都不会默认开启工作通知。普通问答只采纳先收到的真实有效答案，原聊天路由不会改变；执行审批始终留在 Codex。

## 启动方式

**不随 Windows 开机或登录启动，不弹终端窗口。** 启动 Codex 后，MCP / SessionStart 才在后台启动桥接；已有 Dot 隧道也由桥接隐藏启动检查进程。MCP 运行期间检查和恢复连接。桥接服务可能在 MCP 退出后继续运行，本版没有承诺关闭 Codex 就立即停止全部隧道进程。

升级会备份并移除本插件归属校验通过的旧计划任务和 Run 项。旧 `--autostart`、`-RegisterLogon` 和注册计划任务入口被停用。其他软件的启动设置不改动。

## 安装

需要 Windows、Node.js 24+、Python 3.11+ 和可用的 Codex 桌面端。

1. 下载 ZIP 并解压，在 PowerShell 中运行 `./Install.ps1`。安装到当前用户 `.codex/codex-wechat-bridge`，保留已有微信绑定和状态，备份 Codex 配置。
2. 启动或重新加载 Codex，让微信 MCP 加载新版工具。已有聊天仍缓存旧工具时需要重载；旧版卡片调用会被新服务拒绝。
3. 首次绑定运行安装目录的 `open-manager.ps1`，在本机 Edge 管理页完成微信 ClawBot 扫码；已有绑定不必重扫。需要人工立即启动时可运行安装目录 `start.ps1`，或安装时加 `-StartNow`。
4. 若 Codex 提示审阅钩子，按原生流程审阅；安装器不伪造信任，也不更改沙箱、模型或原通知配置。
5. 默认留在电脑答题。只在需要的聊天明确说“微信通知我”，再验证手机实收和答案回到原聊天。

本机控制服务只监听回环地址，使用本机令牌认证。公开包不包含本人账号、状态数据库、DPAPI 密钥、私有隧道配置或隧道客户端二进制。卸载使用 `./Uninstall.ps1`，保留加密凭据和本地证据。

## 简短回复与续办

- 单个待答题：回 `1`、`2` 或自定义文字。
- 多题：回 `1.1`、`2.2` 或 `2.这样改`，点号前是消息中的稳定题号。
- 已答题补充：`5.补充内容` 返回第 5 题的原聊天；重复纯数字不当补充。
- 任务续办：`/3 下一步要求` 返回任务 3 的原聊天；只有一个可续办任务时可用 `/继续任务`。多个任务必须指定编号，`/任务` 查看列表。
- `/clear` 同时清空题号和任务号，包括艾莉丝任务；取消待答及尚未投递的编号提示词。下一个问题和新分配任务从 1 开始；保留模式、聊天、历史、完成去重和已经执行的工作。

微信模式的 `ask_user` 立即返回 `pending`，Agent 将 `local_question_markdown` 显示为聊天文字。微信答案自动投递同一原聊天；电脑真实提示词用 `answer_from_chat` 记录。没有原生问题卡，因此不再需要 computer-use 回填或关闭卡片。普通问题默认 24 小时有效，取消、错误、过期都不是答案。

## 艾莉丝对话和独立工作

`/艾莉丝 对话` 或 `/艾莉丝 文字` 默认直接聊天；对话开启后，无待答问题的普通文字继续交给艾莉丝。`/艾莉丝 退出对话` 退出。待答题、题号补充和任务号命令优先走原路由。

只有 `/艾莉丝 创建任务 具体要求` 或 `/新任务 具体要求` 才创建独立本机 Codex 工作。`/艾莉丝 继续任务 任务号 要求` 只续办明确指定的已登记聊天。服务端区分 conversation/task，普通聊天不能领取工作执行权。新工作仍默认不发通知；在其原聊天明确开启后才推送。

```text
启动 Codex → 隐藏启动本机桥接和已有隧道
微信直接聊天 → 私有事件 → Dot 艾莉丝 → 真实回复
微信明确创建任务 → Dot 调度 → 独立 Codex 聊天（默认不通知）
指定聊天开启微信 → 文字问题/主任务摘要 → 桥接直接提醒
微信答案或题号补充 → 原聊天；电脑提示词也可回答
```

问题和完成提醒标识“艾莉丝提醒”，走已连接的微信出口直接发送，不等待 Dot 生成一轮回复。真正与艾莉丝连续聊天仍依赖云端异步事件：先前两条实测约 44 秒、80 秒，本版不宣称解决了这部分延迟。

## 激活、订阅与验证边界

不需要每轮发送“激活”：绑定用户的新消息可自动更新上下文。限流与普通业务拒绝不再一律清空上下文；HTTP 429 退避 30 秒，最多自动尝试 3 次。结果不确定不重发，明确上下文或登录失效才要求恢复，不能保证平台会话永久有效。
